the scenario

An external MCP server called db-query-agent (Python, STDIO transport) exposes one tool — query_database — that takes a natural-language question, translates it to SQL itself, runs it, and returns rows. ConvEngine never writes SQL here; it just routes the question to the tool and reads back the result. See README.md ("MCP Client") for the DDL/DML this demo assumes.

ce_agent_tool row that makes this legal — the one row people forget
tool_code = 'mcp.db-query-agent.query_database'
tool_group = 'MCP_SERVER'
intent_code = 'DB_QUERY_NLP',  state_code = 'ANALYZE',  enabled = true
# without this row, AgentToolRegistry.requireTool() throws even though the planner already offered the tool

    try it for real

    1) Register the server: POST /api/v1/mcp/servers with {"id":"db-query-agent","transport":"STDIO","command":"python","args":["-m","db_query_agent"]}. 2) Confirm the tool name: GET /api/v1/mcp/servers/db-query-agent/tools. 3) Insert the ce_agent_tool row above (swap in the real tool name). 4) Ask ConvEngine a question that matches your ce_intent_classifier pattern for DB_QUERY_NLP.

    ConvEngine · engine/mcp · McpRegistry / McpClient / McpServerToolExecutor · db-query-agent is an illustrative external MCP server, not shipped with ConvEngine.
